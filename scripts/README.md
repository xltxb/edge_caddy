# scripts/

**每个脚本回答一个问题。** 这份索引写在这里，是因为人是在 `ls scripts/`
之后打开它的——一份文档的组织方式要匹配读它的人当时在做什么。

| 跑什么 | 它回答的问题 | 什么时候跑 |
|---|---|---|
| `python3 scripts/gotest.py [包...]` | 测试过了吗，**没过的是哪一条、为什么** | 代替 `go test ./...` |
| `python3 scripts/probes.py [名字片段]` | **测试拦得住吗，而且拦在点上吗** | 改了被保护的不变量之后 |
| `python3 scripts/probes.py --self-test` | 上面那个脚本自己还好使吗 | 改了 probes.py 之后 |
| `python3 scripts/unread.py` | 有没有**写了但没人读**的 DB 列 / proto 字段 | 加了字段、关了功能之后 |
| `python3 scripts/comments.py` | 三件：注释**首句在讲已经不成立的事**吗；陈述外部行为的理由**挂在会通知你的东西上**吗；**这份索引还准吗** | 写完注释之后、加删脚本之后 |
| `python3 scripts/humantext.py` | 面向人的字符串里，有没有**渲染不出来的标记** | 写完 `msg` / `reason` 之后 |
| `bash scripts/build.sh [版本号]` | 打后端的包（主控 + Agent，交叉编译 Linux amd64/arm64） | 要部署的时候 |
| `python3 scripts/packcheck.py <包>` | 这个包解到目标机器上，**会不会弄坏它落脚的那个目录** | `build.sh` 自动跑，不过就不写校验和 |
| `bash deploy/edge-node_test.sh` | 部署脚本的那些承重约束还在吗 | 改了 `deploy/edge-node.sh` 之后 |
| `sudo bash deploy/cf-realip.sh` | 让审计记下**真实访问者**的 IP，而不是 CDN 的 | 装在 CDN 后面时，以及每月一次 |
| `python3 scripts/dev-restart-master.py` | 重启**本地开发用**的主控（8080 那个），沿用它自己的环境变量 | 提交了新字段之后，前端要拿真主控比形状时 |

## `dev-restart-master.py` 存在的理由是一条跨 agent 的摩擦

前端那套形状检查拿 mock 与**真主控**比，而「真主控」是那个跑着的进程。
后端提交了新字段而进程没重启的话，它比出来的分歧不是「mock 错了」，
是**进程比代码旧**。

这件事撞了三次，每次都要后端这边动手重启。**而那种要另一个人配合的步骤，
最后总会变成「算了这次先不验」** —— 检查还在，只是没人跑它。

所以给两边都留了一个自己能按的口子。它只碰 8080 上那个进程，
不碰灰度、不碰数据库，也不打印任何密钥的值。

## 哪些挂在产物上，哪些靠人记得跑

`build.sh` 会先跑 `humantext.py` 与 `packcheck.py`，任何一条不过就不打包。
判据是：**能让产物不该被发出去的检查，就该挂在产出产物的那一步上。**

- `humantext.py` —— 那些字符串编进二进制、显示在别人的界面上，
  **打包是它们离开这里的最后一刻**
- `packcheck.py` —— 一个会弄坏目标机器的包，不该有校验和

其余的靠人在对的时机跑，而这是**刻意的**（见下一节）。
唯一的例外理由是成本：`probes.py` 要反复改坏源码再跑测试，一次好几分钟，
挂上去的结果是有人开始用别的方式打包——那时它保护的东西一样会溜出去。

> 前端 agent 今天撞到一个更硬的版本：他有三个要连真主控的检查，
> **一个都没接进 `pnpm check`，写完之后基本没跑过**。
> 而其中一个恰好能抓到后来真出的两个 bug。
>
> **一个从没跑过的检查，和一句「以后我会跑」的承诺没有区别。**
> 这份索引因此不只是说明书——它是「这些东西存在」的唯一登记处，
> 而登记了而从不执行的东西，在这里跟执行过的长得一样。

## `precommit-scope.sh` —— 提交的作用域

**同一个工作树、两个 agent**（后端 / `web/`，见 CLAUDE.md）。这条规矩今天破了两次，
方向相反：

| | 动作 | 后果 |
|---|---|---|
| 早上 | `git checkout web/src/model.ts` | 对方未提交的改动**被冲掉**，丢了 |
| 晚上 | `git add -A` | 对方未提交的改动**被收进我的提交** |

第二次没丢数据，代价是**那批改动的理由没进版本库**：提交信息讲的是脚本输出，
底下躺着证书页重构。下一个读它的人会被这条信息送错方向。

同一个根：**git 操作的作用域覆盖了别人的目录**。
「提交前看一眼 `git status`」是一句承诺，而提交正是改动离开这里的那一步——
所以门挂在那里，不挂在我记性上。

它**不在版本库里**（`.git/hooks/` 不被跟踪），装法：

```sh
printf '#!/usr/bin/env bash\nexec "$(git rev-parse --show-toplevel)/scripts/precommit-scope.sh"\n' \
  > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

卸掉就 `rm .git/hooks/pre-commit`；单次绕过用 `git commit --no-verify`。
**留着逃生口是有意的**：一道关不掉的门迟早会被整个卸掉。

测试 `precommit-scope_test.sh`（4 条，在临时仓库里跑，不碰真索引）。
其中「跨接缝要被拒」那条是承重的——**只有它证明钩子真的在跑**；
另外两条「允许通过」在钩子根本没装上时同样是绿的。

## 每个脚本都要说出「查了多少」

**绿色的意思是「没有坏消息」，而「根本没跑」也满足「没有坏消息」。**
两者走的是同一条输出路径，所以它一直能得逞——今天数到第八次。

能挡住它的只有一类东西：**要求正面证据的检查**。所以这里每个脚本的收尾
必须报出规模，不能只报结果：

| 只说结果（不够） | 说了规模（够） |
|---|---|
| `共 0 项没人读` | `查了 193 项，其中 0 项没人读` |
| `没有渲染不出来的标记` | `2611 个字符串里没有…（扫了 72 个文件）` |
| `通过` | `通过=282 失败=0` |

配套的是装置自检：抽不到东西就报错退出，而不是印一行 0 然后说全过了。
`unread.py` 有两条——一条守输入（源码真的读到了），一条守抽取
（源码读到了而正则坏了的话，输入那条照样绿）。

### 判词放最后一行

`| tail -1` 是最省事、因此最常见的读法。`comments.py` 原先把失败印在最前面、
把 ✓ 印在最后，于是 tail 永远看到一行绿的——**我就这么读了它一整晚，
它连续几次报错退出 1 而我没看见**。

**让偷懒的读法也是对的读法。** 与其要求自己别用 tail，不如让 tail 说真话。

## 为什么不是一条 `make check`

它们的**触发时机不同**，而合成一条会让每一条都在不需要它的时候跑。
`gotest.py` 每次都该跑；`unread.py` 只在结构变了之后有意义；
`probes.py` 要真的改坏源码再还原，慢且有副作用。

合成一条的代价不是时间，是**人会开始忽略其中几条的输出**——
而那时它们跟不存在没有区别。

## 三条共同的规矩

**先证明自己不瞎。** 每个脚本都有装置自检：`gotest.py` 在「一条测试都没跑」
时非零退出（编译失败、名字打错、全被 skip 都长成「0 失败」）；
`unread.py` 读不到十万字节 Go 源码就报错；`comments.py` 找不到二十个文件就报错；
`humantext.py` 扫不到 20 个文件或 200 个字符串就报错；
`packcheck.py` 遇到少于 3 个条目的归档直接判装置坏了（空归档会让每一条都平静通过）。

> 一次什么也没找到的扫描，要先证明它能找到什么。

**误报要修，不要豁免。** 加豁免会把「扫描不准」记成「这条不用管」，
那是两件不同的事，而记错之后没人会再回来分辨。

**盲区要说清，跟误报一样。** `unread.py` 的判据是「名字出现过吗」，
所以 `at` / `id` / `msg` 这类短名会假阴性。不说的话，「0 项是新的」
会被读成「确实没有新问题」。`humantext.py` 不看反引号原始字符串
（正则、SQL、JSON 模板住在那里），也看不见拼接出来的标记。

> 说清误报是在保护**真阳性**，说清盲区是在保护**真阴性**。两句都不是道歉。

**这份索引自己会红。** 一份手写的索引正是最会过期的东西，
而**索引过期不会有任何东西报错**——它只在有人照它做的时候才显形。
`comments.py` 双向核对：这里提到的脚本必须存在，**存在的脚本必须被提到**。

后者是关键。只查前一个方向的话，「加了脚本忘了写索引」永远不会被发现
——而那正是索引最常见的坏法。
