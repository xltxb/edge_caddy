# 控制台部署

主控 + 控制台界面装在**一台机器**上。这份文档按你实际会敲的顺序写。

节点怎么装见 [README.md](README.md)——**但先装主控**：节点的接入 Token
要从控制台里签，没有主控就没有 Token。

---

## 0. 准备

| | |
|---|---|
| 一台 Linux 机器 | amd64 或 arm64 |
| PostgreSQL 16 | 可以在同一台机器上 |
| 一个域名 | 节点靠它连回来。**可以挂在 CDN 后面**，见下 |
| nginx | 前置反代，终止 TLS。**不是可选的**，除非全走内网，见下 |

**不需要 root。** 主控自己只监听回环，也不写系统目录——用一个专用账号跑就行。

### 两种形态，先决定用哪一种

| | 控制台怎么访问 | 节点怎么连回来 | 什么时候选它 |
|---|---|---|---|
| **对外**（本文默认） | 域名 + nginx + TLS | `wss://` 穿 443 | 节点在公网上。域名可以挂 CDN |
| **纯内网** | SSH 隧道到 `127.0.0.1:8080` | 直连 `host:9000` | 主控和节点在同一张内网里 |

这份文档按**对外**那一种写。纯内网的差别只有两处：跳过 nginx 那一节，
`EC_ADVERTISE` 写成 `host:9000`。

> 域名那条不是可选项：`EC_ADVERTISE` 填 IP 主控**拒绝启动**。
> 理由是换地址那天——用 IP 的话每台节点的 `--master` 都要挨台改，
> 改完之前它们全部连不上；用域名改一条 DNS 记录，节点无感。

## 1. 拿包、解包

```bash
# 专用账号先建出来：后面每一步都要用它的身份，而不是 root 的
sudo useradd --system --home /opt/edge --shell /usr/sbin/nologin edge

# 两个架构选一个
tar xzf edge-controller-<版本>-linux-amd64.tar.gz
sudo install -m 0755 linux-amd64/master /usr/local/bin/edge-master

# 前端产物解到一个固定位置
sudo mkdir -p /opt/edge/web
sudo tar xzf edge-console-<版本>.tar.gz -C /opt/edge/web --strip-components=1

# **解完必须重设属主和模式，不能让 tar 包决定。** 理由见下面那段警告。
sudo chown -R edge:edge /opt/edge/web
sudo chmod -R u=rwX,go=rX /opt/edge/web

# 用 edge 的身份验一遍——用 root 验等于没验
sudo -u edge test -r /opt/edge/web/index.html && echo "edge 读得到" || echo "edge 读不到"
```

> ⚠️ **解包永远带 `-C <目标目录>`，绝不 `cd` 进一个系统目录再解。这一条是灰度上用血换的。**
>
> 归档里那个顶层 `./` 条目**自带属主和模式**。以 root 用 GNU tar 解包时，
> 它会被**还原到解包的那个目录本身**上。所以
>
> ```bash
> cd /opt && sudo tar xzf edge-console-*.tar.gz     # ← 千万别这么干
> ```
>
> 会把打包机器上那个目录的属主和模式**印到 `/opt` 上**。
> 灰度上真实发生过，`/opt` 变成了：
>
> ```
> drwx------ 501 staff  opt
> ```
>
> 0700，属主是 **UID 501 / 组 staff**——那是 **macOS** 的账号，这台 Debian 上
> 根本没有 501 这个用户。**结果是这台机器上任何非 root 用户都进不了 `/opt`**，
> 控制台只是第一个撞上的。
>
> 带 `-C` 就不会波及上级目录。而 `chown` / `chmod` 那两行仍然要跑：
> 归档对**目标目录**仍然有意见。

### 读不到的时候，先看整条路径

```bash
namei -l /opt/edge/web/index.html
```

**权限是逐层检查的。** `edge` 要读那个文件，得能穿过 `/`、`/opt`、`/opt/edge`、
`/opt/edge/web` 每一层，最后还得能读它——**任何一层缺 `x`，症状都是同一句
「读不到」**。

而 `ls`（用 root 跑）一路畅通，它永远告诉你文件在。所以：

> **用 root 验等于没验。**

`namei -l` 不回答「那个文件怎么了」，它回答「这条路每一层分别怎么了」——
坏的那一层完全可能跟这个项目毫无关系。

包里还有 `edge-agent` 和 `edge-node.sh`——**那两个是给节点的**，
主控机器上用不到（除非这台机器同时也当节点，见文末）。

## 3. 配置

建一个只有它自己能读的文件——**凭据不进命令行**：

```bash
# useradd 第 1 步已经建过，这里只补目录属主（重复跑会说「已存在」，无害）
sudo mkdir -p /opt/edge && sudo chown edge:edge /opt/edge

sudo tee /etc/edge-master.env >/dev/null <<'EOF'
EC_DATABASE_URL=postgres://edge:那个口令@127.0.0.1:5432/edge_controller?sslmode=disable
EC_SECRET_KEY=用 openssl rand -base64 48 生成，至少 32 字节
EC_ADVERTISE=wss://cdn.example.com    # 见下面「节点怎么连进来」
EC_WEB_ROOT=/opt/edge/web
EC_HTTP_ADDR=127.0.0.1:8080
EC_GRPC_ADDR=127.0.0.1:9000           # wss:// 时不必对外，见下
EC_ACME_EMAIL=you@example.com
EC_ACME_DIRECTORY=https://acme-staging-v02.api.letsencrypt.org/directory
EOF
sudo chmod 600 /etc/edge-master.env
sudo chown edge:edge /etc/edge-master.env
```

### 节点怎么连进来：两种写法，选一种

`EC_ADVERTISE` 是主控**对节点公布的地址**。它原样进安装命令（`--master <它>`），
所以改这一个变量就够了——不需要第二个「模式」开关。

| 写法 | 节点走哪条路 | 什么时候用 |
|---|---|---|
| `wss://cdn.example.com` | 隧道走 WebSocket，**穿 443** | **默认选它。** 域名可以挂在 CDN 后面，企业出站策略也只放行 443 |
| `ec.example.com:9000` | 直连 gRPC 端口 | 主控直接暴露、中间没有 CDN 时 |

> ⚠️ **域名挂在 CDN（Cloudflare 橙云等）后面时，必须用 `wss://` 那种写法。**
>
> CDN 只代理 80/443，`9000` 那样的端口它不转发。而这件事的失败方式很难看：
> **主控启动正常、校验通过、节点装完一切正常，然后节点永远不出现在控制台里**，
> 那台机器上没有任何东西说得出为什么。灰度上撞到过。
>
> 现在装机脚本会在**动那台机器之前**先试连一次，连不上就拒绝安装并点名这个成因。

两种写法下**里层完全一样**：同一套 mTLS、同一个内部 CA、同一个 CA pin。
节点身份始终是内部 CA 签发的客户端证书（ADR-0009），
**中间那层 CDN 只看得见外层 TLS，隧道里的东西对它是不透明的**——
下发走内联证书（ADR-0010），每个客户域名的私钥都在这条隧道里传。

用 `wss://` 时 `EC_GRPC_ADDR` 可以不再对外开放（只留给同机调试），
防火墙上那条 9000 的规则可以撤掉。

### 必填的三个

| 变量 | 不填会怎样 |
|---|---|
| `EC_SECRET_KEY` | **拒绝启动**。DNS / Lark 凭证与两套 CA 的根私钥都用它加密 |
| `EC_ADVERTISE` | **拒绝启动**。必须是域名，填 IP 也拒绝 |
| `EC_DATABASE_URL` | 默认值连本机 `edge_controller`，密码不对就起不来 |

> **`EC_SECRET_KEY` 丢了等于两套 CA 的根私钥丢了。** 存进密码管理器，
> 别只放在这台机器上。

### 其余的

| 变量 | 默认 | 说明 |
|---|---|---|
| `EC_WEB_ROOT` | `web/dist` | **控制台静态文件**。默认是相对路径，systemd 起服务时工作目录是 `/`，所以**一定要写绝对路径**（见第 5 步的日志确认） |
| `EC_HTTP_ADDR` | `127.0.0.1:8080` | 控制台的监听地址。**只绑内网或回环**，见下 |
| `EC_GRPC_ADDR` | `0.0.0.0:9000` | 直连隧道的监听地址。**用 `wss://` 时把它绑回环**（`127.0.0.1:9000`），节点不走它 |
| `EC_ACME_EMAIL` | 空 | 签证书用。不填则**签发不了证书**，其余功能正常 |
| `EC_ACME_DIRECTORY` | Let's Encrypt 生产 | **首次建议先指 staging**（上面那行），它的速率限制宽得多，签废了也不心疼 |
| `EC_SESSION_TTL_HOURS` | `12` | 登录多久过期 |
| `EC_OPS_BOT_TOKEN` | 空 | 给 ops-bot 的静态 Token，不用就别设 |
| `EC_MTLS` | `0` | **只能是 0**，翻开会拒绝启动（那一半没实现，见 [ADR-0013](../docs/adr/0013-console-access-is-network-plus-session.md)） |

还有几个是**主控用来渲染节点配置**的，通常不用动：
`EC_EDGE_HTTP_LISTEN`（`:80`）、`EC_EDGE_HTTPS_LISTEN`（`:443`）、
`EC_VERIFY_ADDR`（`127.0.0.1:2020`）、`EC_UPSTREAM_CERT` / `EC_UPSTREAM_KEY`。

### `EC_HTTP_ADDR` 绑错地方不会有任何东西报警

控制台的准入是「**只绑内网或回环** + 会话 Cookie + 全写审计」
（[ADR-0013](../docs/adr/0013-console-access-is-network-plus-session.md)）。

**「只绑内网」是部署形态，不是代码里的检查**——绑成 `0.0.0.0` 代码不会拒绝，
也不会有任何东西报警，而控制台就暴露在公网上了。

**两种形态下它都该是回环**：对外形态里对外的是 nginx，主控在它后面；
绑成 `0.0.0.0` 等于在 nginx 旁边又开了一个**没有 TLS、没有那些安全头**的入口，
而它不会出现在任何一份配置里，也不会有人去检查它。

纯内网形态下远程访问走 SSH 隧道：

```bash
ssh -L 8080:127.0.0.1:8080 你的主控机器
# 然后本地浏览器打开 http://127.0.0.1:8080
```

## 4. 初始化

三条命令，都是跑完就退出。用 `systemd-run` 而不是手工 `export`——
**它用 systemd 自己的解析读那个文件，跟服务跑起来时是同一套**：

```bash
run() { sudo systemd-run --uid=edge --pipe --wait --quiet \
          --property=EnvironmentFile=/etc/edge-master.env \
          /usr/local/bin/edge-master "$@"; }

run -migrate                              # 建表
run --create-user 'abiu:你的口令'          # 建控制台账号
run -ca-pin                               # 打印 CA 指纹，加节点时要用
```

> **为什么不用 `env $(cat … | xargs)`。** 那个写法会被值里的引号、
> 空格、反斜杠吃掉——而 `EC_DATABASE_URL` 里的数据库口令可以是任何字符。
> 更麻烦的是它**不一定出错**：变形之后的口令连不上库，报的是
> 「认证失败」，而人会去查数据库账号。
>
> 用 systemd 自己的解析还消除了另一类：**手工跑通了、服务却起不来**
> ——那时两边读的是同一个文件，而解析规则不同。

`--create-user` 对已存在的账号是**重置口令**，忘了口令用同一条命令改。

## 5. 起服务

```bash
sudo tee /etc/systemd/system/edge-master.service >/dev/null <<'EOF'
[Unit]
Description=Edge Controller 主控
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
User=edge
Group=edge
# 凭据只在 EnvironmentFile 里，绝不进 ExecStart —— 命令行参数出现在 ps 输出里
EnvironmentFile=/etc/edge-master.env
ExecStart=/usr/local/bin/edge-master
Restart=always
RestartSec=3

# 沙箱：主控不需要 root，也不写系统目录
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ProtectKernelTunables=yes
ProtectControlGroups=yes
RestrictSUIDSGID=yes
# 只有这一个目录可写（如果你把 WEB_ROOT 放在别处，这里不用加——它只读）
StateDirectory=edge-master

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now edge-master
```

### 确认它起对了

```bash
sudo journalctl -u edge-master -n 20 --no-pager
```

**看这三行**：

```
INFO 主控启动 version=v0.2.0 (f291d7f)
INFO 控制台静态文件 web_root=/opt/edge/web
INFO gRPC 隧道监听 addr=127.0.0.1:9000
INFO HTTP 监听 addr=127.0.0.1:8080 ca_pin=9946b79d…
```

用 `wss://` 时第三行绑回环是对的——**节点不走它**，走的是第四行那个 HTTP 面上的
`/api/v1/tunnel`。`ca_pin` 那串加节点时要用，控制台里也会给。

第二行是最容易出错的一处，而它有**两种**说法，指向完全不同的地方：

```
WARN 控制台静态文件不在，主控只提供 API web_root=/web/dist err=... 提示=把前端产物解到那里，或者把 EC_WEB_ROOT 指过去
```

说明 `EC_WEB_ROOT` 没设或者写成了相对路径——**systemd 的工作目录是 `/`**，
`web/dist` 会解析成 `/web/dist`。API 照常工作，只是打开控制台会看到一段说明。

```
WARN 控制台静态文件读不到（没权限，不是不在）… 提示=先看 namei -l /opt/edge/web/index.html
```

**文件在那儿，而主控进不去。** 这一句和上一句必须分开读：
`ls` 用 root 跑会显示文件都在，于是「不在」那句话会把人送去查解包，
而问题在权限——而且**可能在路径上任何一层**，包括跟这个项目毫无关系的
`/opt` 本身。灰度上就是这样。

**第一行的版本号要跟你推上去的那一版对得上。** 它是 `-ldflags` 注入的，
不是硬编码的常量——如果它跟你以为的不一样，说明推上去的不是你以为的那个包。

## 6. 前置 nginx

**只在纯内网形态下才是可选的。** 对外部署时它承担两件事，
而第二件常被忘掉：

1. 终止 TLS、把控制台暴露出去
2. **节点隧道也从它这里过**（`/api/v1/tunnel`）——用 `wss://` 时，
   漏了那段 location，节点连不进来

配置见 [nginx-console.conf](nginx-console.conf)，
**照着做的步骤见 [nginx部署.md](nginx部署.md)**（装、证书、SELinux、验证四条）。

**先说清这会改变什么。** ADR-0013 定的准入是「只绑内网或回环 + 会话 Cookie
+ 全写审计」，远程访问走 SSH 隧道。**前置反代并把它暴露出去，就是换掉了第一条**
——那一条的强度从此取决于 nginx 的配置，而不再取决于网络位置。

（ADR-0013 反对前置 Caddy 的两个理由，只有一个对 nginx 成立：
「机器上多一个要跟版本、要打 CVE 的组件」。
另一个——「主控上的 Caddy 和节点上的 Caddy 会被混为一谈」——nginx 不会。）

**主控那边要多配两个变量**，而它们漏了都不会有明显症状：

```bash
EC_SECURE_COOKIE=1          # nginx 终止 TLS，主控自己看到的是 HTTP
EC_TRUSTED_PROXIES=127.0.0.1
```

| 漏了会怎样 | |
|---|---|
| `EC_SECURE_COOKIE` | 会话 Cookie 不带 `Secure` 标志。**它仍然能用**，所以这个疏漏一点症状都没有 |
| `EC_TRUSTED_PROXIES` | 审计日志里的来源 IP **全部**变成 `127.0.0.1`（nginx 自己） |

> **主控默认「谁也不信」是有理由的。** gin 的默认是信任所有代理，
> 那时任何能访问控制台的人发一个 `X-Forwarded-For: 1.2.3.4` 就能让审计
> 记下那个 IP——**而审计是这套准入模型的三分之一**。
> 所以只有 `EC_TRUSTED_PROXIES` 里列出的地址转来的 `XFF` 才作数。

### 前面还有一层 CDN 的话，再做一步

**域名挂在 Cloudflare 之类的 CDN 后面时，上面那些配全了也不够。**

nginx 看到的对端是 CDN 边缘节点，不是访问者。于是审计日志里每一条都记着
CDN 的 IP——**这比记 `127.0.0.1` 更难发现**：它看起来像一个真实的公网地址，
人不会怀疑它。（灰度上就是这样，是逐条检查响应头时才发现的。）

```bash
sudo ./cf-realip.sh          # 生成可信来源表、nginx -t、reload
sudo ./cf-realip.sh --dry-run  # 只看要写什么
```

它从 Cloudflare 公布的列表生成 `/etc/nginx/conf.d/cloudflare-realip.conf`，
配合 `nginx-console.conf` 里那两行 `real_ip_header` / `real_ip_recursive` 生效。

**地址段会变，挂个定时任务每月跑一次**：

```bash
sudo cp deploy/cf-realip.sh /usr/local/sbin/
echo '17 4 1 * * root /usr/local/sbin/cf-realip.sh >/dev/null' \
  | sudo tee /etc/cron.d/cf-realip
```

> **不要手抄一份 IP 段进 nginx 配置。** 它会过期，而过期的表现是
> 「某些访问者的 IP 又变回 CDN 的地址」——没有任何东西会报错。
>
> 绕过 CDN 直连源站的人伪造不了 `CF-Connecting-IP`：real_ip 只对
> `set_real_ip_from` 里列出的对端生效，而他不在那张表里。
> 文件缺失时这一段整体失效，来源 IP 退回 CDN 的地址——
> **降级，而不是变得可伪造**。

验证方式只有一个，而且必须真的做：**登录控制台，然后看审计页那条记录的
来源 IP 是不是你自己的公网地址。**

**证书用 certbot 之类另外签**。不要用本系统签的——那两套 CA 是给隧道和回源
用的内部 PKI，浏览器不认它们。

## 7. 打开控制台

对外形态：浏览器直接开 `https://你的域名`。

纯内网形态：

```bash
ssh -L 8080:127.0.0.1:8080 你的主控机器
# 浏览器开 http://127.0.0.1:8080
```

用第 4 步建的账号登录。

**这时总览页上什么都没有是正常的**：还没有节点。

> **登录之后立刻做一件事：翻到审计页，看那条登录记录的来源 IP。**
>
> 它应当是你自己的公网地址。是 `127.0.0.1` 说明 `EC_TRUSTED_PROXIES` 没配；
> 是一个陌生的公网地址说明 CDN 那一层没处理（第 6 步末尾那一段）。
>
> **这两种都不会报错**，而审计是这套准入模型的三分之一。

## 8. 加第一台节点

控制台 → 边缘节点 → 添加节点，填好之后它给你两条命令。

那两条命令**都是相对路径**（`./edge-node.sh`、`--agent-bin ./edge-agent`），
所以先把这两个文件送到那台机器上：

```bash
scp linux-amd64/edge-node.sh linux-amd64/edge-agent root@node-hk-01:/root/
```

然后照控制台给的命令跑。

**装机脚本在动那台机器之前会先试连一次主控。** 连不上就拒绝安装，
并点名最常见的三个成因（域名被 CDN 代理、防火墙没放行、主控只绑了回环）。

> 这一步不是保险，是**真前提**：连不上隧道，这次安装无论如何不可能工作。
> 少了它，装机会一路成功——装 Caddy、写单元、起 Agent——
> 然后节点**永远不出现在控制台里**，而那台机器上没有任何东西说得出为什么。

**`verify` 那条也别跳过**——它查的是 Caddy 的 Admin
有没有暴露在回环之外，而证书私钥是内联在运行配置里的
（[ADR-0010](../docs/adr/0010-cert-distribution.md)），能读 Admin 就能读到它们。

详见 [README.md](README.md)。

## 出问题时先看这张表

**这些症状每一个都指向错的地方**，都是灰度上真撞过的。

| 你看到的 | 多半是 | 先跑什么 |
|---|---|---|
| 「控制台的静态文件**不在**」，而 `ls` 明明有 | `EC_WEB_ROOT` 指错，或者真没解包 | `journalctl -u edge-master \| grep 静态文件` |
| 「控制台的静态文件**读不到**」，而 `ls` 明明有 | 路径上某一层主控进不去 | `namei -l /opt/edge/web/index.html` |
| 节点装完了，**永远不出现在控制台里** | 隧道到不了主控（CDN 不转 9000 最常见） | 装机脚本已经会先试连并拒绝安装；旧节点用 `nc -vz <host> <port>` |
| 审计里来源 IP 全是 `127.0.0.1` | `EC_TRUSTED_PROXIES` 没配 | 见第 6 步 |
| 审计里来源 IP 是个陌生的公网地址 | 那是 CDN 的地址，real_ip 没配 | `sudo ./cf-realip.sh` |
| 节点**反复上下线** | nginx 那段 `/api/v1/tunnel` 的超时太短 | 见 nginx-console.conf |
| 浏览器控制台里一堆红色报错 | 多半不是我们的 | 开无痕窗口再看一遍；扩展的报错也印在同一个地方 |

三条通用的：

1. **`ls` 用 root 跑，主控不是 root。** 用 root 验等于没验——
   验权限要用 `sudo -u edge`。
2. **权限是逐层检查的。** `ls -ld <那个目录>` 只回答「这一层对不对」，
   而人已经默认问题在这一层了。`namei -l <完整路径>` 才回答「哪一层」。
3. **绕开一层再问一次。** 分不清是主控还是 nginx 的问题时，
   `curl http://127.0.0.1:8080/` 直连主控——一次就能把范围砍一半。

## 会拒绝启动的三种

主控**宁可起不来也不装作起来了**。三种情况，错误信息都会说清怎么办：

| 现象 | 原因 |
|---|---|
| `EC_SECRET_KEY 未设置` | 它加密着两套 CA 的根私钥，没有它主控不该启动 |
| `EC_ADVERTISE=… 是 IP，这里要求域名` | 见开头那段 |
| `EC_ADVERTISE=… 的协议是 "https"` | 隧道走 `wss://`，不是 `https://`。**不会被悄悄纠正**——纠正了的话写错的人学不到这个区别，下一次会在 nginx 配置里再写错一遍 |
| `EC_MTLS 打开了，而控制台的 mTLS 还没有实现` | 那个开关此前唯一的效果是把 Cookie 标成 `Secure`，而那会让你在纯 HTTP 上**登录不上**——一个跟 mTLS 无关的故障 |

**配置错误走 stderr，不走 JSON 日志**：那几条是写给人现场照着改的，
有多行、有示例，压进 JSON 就读不了了。

## 用外部平台的证书

不想让主控自己跑 ACME 的话，可以从别的证书平台导入：

```bash
curl -X PUT https://console.example.com/api/v1/certs/api.example.com \
  -b cookies.txt -H 'Content-Type: application/json' \
  -d "$(jq -n --rawfile c fullchain.pem --rawfile k privkey.pem \
        '{cert_pem:$c, key_pem:$k}')"
```

`fullchain.pem` 要**含中间证书**——只给叶子的话接口不拒绝，但会在
`warnings` 里说明：部分客户端（老 Android、某些 Java 运行时）会握手失败，
而另一些完全正常。

**导入的证书主控不会自动续期**（它续不了一张不是它签的），到期前要再导一次。
接口回的 `days_left` 是当前剩余天数。

成功即已下发到各节点。校验不过的会在**存之前**拒绝，
`msg` 说清是哪一种——最常见的是传错了文件，那时它会告诉你
那张证书**实际覆盖的是哪个域名**。

详见契约 §9。

## 主控能不能和节点同机

**能，但要先想清端口。**

节点上的 Caddy 要绑 `:80` 和 `:443`，而主控绑 `8080` / `9000`——不冲突。
真正要注意的是两条：

- **主控不装 Caddy**（[ADR-0013](../docs/adr/0013-console-access-is-network-plus-session.md)）。
  同机的话那台机器上会有一个 Caddy，而它属于节点那一侧。排查时
  「主控上的 Caddy」和「节点上的 Caddy」很容易被混为一谈。
- 那台机器同时是流量入口和控制面。**它挂了你两样都没了**，
  而控制面本该是用来修流量的那个。

灰度可以同机，正式环境建议分开。
