# 配置漂移只比对版本号，不回读节点配置

「配置漂移」是集群总览的四项 KPI 之一，两种定义都说得通：比对节点上报的 `cfg_version`
与当前基线（回答「这次下发到没到」），或让 Agent 回读本机 Caddy 的实际配置与主控渲染的
字节比对（还能回答「到了之后有没有被改」）。选前者。

## Consequences

- 手工 SSH 上节点改配置、节点重启后回退到旧配置、下发只应用了一半——这些情况下版本号
  照旧正确，**漂移不会亮**。KPI 显示「全部一致」时，其含义只是「最近一次下发都到达了」。
- 这个局限必须在界面上说清楚。一个叫「配置漂移」的指标，读者会理所当然地以为它能发现篡改；
  不说明就等于用界面措辞给出一个它兑现不了的承诺。
- 改成内容比对是后续可做的增量：需要 Agent 增加回读上报、主控增加比对。但「比什么」要先想清楚
  ——Caddy 会给配置回填默认值，拿渲染字节与回读字节直接比会恒为漂移，须比对规范化后的形式
  或主控渲染内容的 checksum。
