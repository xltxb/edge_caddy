# 只重试传输层失败，Caddy 拒绝的配置不重试

后端文档 §6 让所有失败节点进重试队列（指数退避、上限 5 次）。实测发现按状态码无法分类：
Caddy 对 JSON 语法错误、未知 handler、字段类型错、端口被占用**一律返回 500**。改为按
「节点有没有回应」分类——节点未回应（超时 / 连接断开）才重试，节点回应了但 Caddy 拒绝
配置则不重试，直接把 Caddy 的原文报错展示在该节点那一行。

## Consequences

- 一份写错的配置不会在日志里刷 5 遍一模一样的报错。重试对它无效——同一份字节喂给同一个
  Caddy 必然得到同一个拒绝，能修它的是人改配置，不是时间。
- 代价是环境类临时故障（端口被别的进程短暂占用）不再自愈。这类情况会以失败留在该节点那一行，
  由人点「重推」恢复——`POST /nodes/:id/push` 本来就是 P0 接口，不必为此另造机制。
- 不去解析 Caddy 的错误文本来分类。那样分得最准，但会把重试逻辑绑死在 Caddy 的报错措辞上，
  措辞一改我们就静默失效——**静默**是这里的关键：分类失效不会报错，只会开始做错误的重试决策。
